# HANDOFF — pi-foreman

Tier: poc

最終更新: 2026-09-22

## これは何か

pi に 2 つの層を足す拡張。判定は TypeSafe の jev（確率が返る判定モデル）。

- **foreman** — 着手前に 1 回、タスクを見立てて助言を注入する（[ADR 0001](adr/0001-jev-routing-layer.md)）
- **gate** — ツール実行の直前に、危ない操作を知らせる（[ADR 0002](adr/0002-gate.md)）

どちらも助言・通知どまりで、既定では何も止めない。

## 動いていること（実測済み）

- 質問文のフィクスチャ 15/15（`npm run fixtures`）
- `pi -e .` で foreman の見立てがモデルに届く
- gate が `tool_call` 経由で `bash` と `write` の両方で発火。判定は
  `~/.pi/agent/foreman-gate.log` に残る
- gate の眼目である「jev に聞かずに済む事実」は `npm run gate:live` で比較できる。
  `rm -rf build`（git の無視対象）は jev 単独なら止まるが、事実と併せると通る

## 触るときの注意

- **質問文を 1 語でも変えたら `npm run fixtures` を回す。** 実測で 3 回、
  「良くしたつもりの書き換えが別の項目を壊す」現象が起きている。直近の例は
  `visual` から「data files は UI でない」を外したら全体のスコアが押し上がり、
  DB マイグレーションが 0.09 → 0.57 になった件
- **フィクスチャが緑なのは、主張した項目についてだけ。** 負例を書いていない項目は
  静かに壊れる。上の件はまさにそれで見逃しかけた
- `npm run backtest` の出す数は**率ではない**。`!!` の行を 1 件ずつ読む道具
- プロンプト本文はそのまま TypeSafe に送られる。社外秘を含む環境では層ごと切ること
