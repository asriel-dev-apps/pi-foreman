# HANDOFF — pi-foreman

最終更新: 2026-09-23

## これは何か

pi の拡張と、Claude Code・Codex 共通のフック（`bin/hook.ts`）。依頼を受けたときと、rv・HTML レポートの入口で
進め方の助言を注入する（[ADR 0001](adr/0001-jev-routing-layer.md)、[ADR 0003](adr/0003-claude-codex-and-send-policy.md)）。
依頼時の判定は TypeSafe の jev（確率が返る判定モデル）。入口での判定は手元の事実だけ。助言どまりで何も止めない。

送る範囲は対象リポジトリの `Jev:` 行で決まる。既定は何も送らず手元のルール表、`Jev: full` のときだけ全文を jev に（ADR 0003）。

実行前の安全弁（gate）は 2026-09-23 に削除した。gate は jev に頼らず決定論的に行う方針のため
（[ADR 0002](adr/0002-gate.md) は撤回扱い）。

## 動いていること（実測済み）

- 質問文のフィクスチャ 19/19、holdout 10/12（`--mode full`、2026-09-23）。落ちたのは README 手順の更新 size 0.72 と決済の冪等キー risky 0.40
- `npm run check` がネットワーク無しで緑（ルール表・射影に依頼文が出ないこと・入口の判定・フックの入出力）
- `pi -e .` で foreman の見立てがモデルに届く

## 触るときの注意

- **質問文を 1 語でも変えたら `npm run fixtures` を回す。** 実測で 3 回、
  「良くしたつもりの書き換えが別の項目を壊す」現象が起きている。直近の例は
  `visual` から「data files は UI でない」を外したら全体のスコアが押し上がり、
  DB マイグレーションが 0.09 → 0.57 になった件
- **フィクスチャが緑なのは、主張した項目についてだけ。** 負例を書いていない項目は
  静かに壊れる。上の件はまさにそれで見逃しかけた
- `npm run backtest` の出す数は**率ではない**。`!!` の行を 1 件ずつ読む道具
- 既定（`Jev:` 行なし）では依頼文の文字列は送られない。`Jev: full` の repo だけ全文が出る
