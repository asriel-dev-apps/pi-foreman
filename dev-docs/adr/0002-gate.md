# ADR 0002: 実行前の安全弁を同じリポジトリに置く

- Status: Withdrawn (2026-09-23) — gate は jev を使わず決定論的に行う方針にしたため、実装を削除した
- Date: 2026-09-22
- 参考実装: [pi-jev](https://github.com/y0usaf/pi-jev)

## 背景

ADR 0001 の foreman は着手前に 1 回だけ喋る。走り出したあとの `rm -rf` は見ていない。
pi-jev はそこを見る拡張で、`bash` / `write` / `edit` の実行前に 4 問を投げ、
閾値を超えたら知らせる (既定) か確認を出す (enforce)。

同じ jev クライアント・同じ fail open の作法・同じフィクスチャの回し方を使うので、
別リポジトリにすると全部が二重になる。**同じリポジトリの 2 本目の拡張とする。**

## 決定: 事実は手元で確定させ、jev には判断だけを問う

pi-jev の弱点は実測で出る。「ビルド成果物を消して」という依頼つきで `rm -rf build` を
問うと `destructive` は **0.97**。pi-jev の閾値は 0.90 なので、当たり前の要求が毎回
引っかかる。jev は `build/` が `.gitignore` に載った再生成可能なディレクトリだと
知りようがない。**それは判断ではなく事実であり、手元で `git check-ignore` を叩けば済む。**

したがって実行前に、jev に聞かずに確定させることを先に確定させる。

| 事実 | 調べ方 |
|---|---|
| 読むだけのコマンドか | コマンド名と、リダイレクトを含まないこと |
| 対象が git の無視対象か | `git check-ignore` |
| 対象に未コミットの変更があるか | `git status --porcelain -- <paths>` |
| git の履歴を書き換えるか | `push --force` / `reset --hard` / `rebase` などの形 |
| 作業ディレクトリの外を触るか | パスの解決結果 |
| git が知らないファイルを上書きするか | 存在する ∧ `git ls-files` に無い ∧ 無視対象でもない |

これを使って、jev の答えを 2 方向に補正する。

- **通す方向**: `destructive` が閾値を超えても、対象がすべて git の無視対象で、履歴も
  書き換えないなら止めない
- **止める方向**: 未コミットの変更を含む削除、履歴の書き換え、作業ディレクトリの外への
  操作、git が追跡していない既存ファイルの上書きは、jev のスコアによらず理由として出す
  (jev には見えない事実だから)

同じ「上書き」でも事情は 3 通りに分かれ、jev にはどれも同じ文字列にしか見えない。
追跡済みファイルの上書きは git から戻せる。無視対象は元から git の外にある。
**存在するが追跡されておらず無視対象でもないファイルの上書きだけが、本当に戻らない。**

実測 (同一の疑似リポジトリ、`scripts/gate-check.ts --live`):

| コマンド | jev のスコアだけ | 事実と併せて |
|---|---|---|
| `rm -rf build` (無視対象) | 止める | **通す** |
| `rm -rf src` (追跡済み) | 止める | 止める (破壊的 0.95) |
| `rm notes.md` (未コミットあり) | 止める | 止める (＋ git から戻せない) |
| `git push --force origin main` | 止める | 止める (＋ 履歴を書き換える) |
| `curl -X POST -d @.env ...` | 止める | 止める (外部送信 0.97) |
| `ls -la` / `git status --short` | 1 往復 | **API を呼ばない** |

## 決定: ファイルの中身は送らない

pi-jev は `write` / `edit` の引数を先頭 400 文字まで送る。「破壊的か」の判定に中身は
要らないので、`content` / `old_string` / `new_string` は長さと行数に置き換える。
送らなければ漏れない。読むだけのコマンドで API を呼ばないのも同じ理由による。

## 既定は shadow

pi-jev と同じ。知らせるだけで止めない。`/gate enforce` で確認を出す形に変えられる。
確認 UI のない headless (`-p`, RPC) では、enforce でも止めずに警告に落とす。

## 既知の限界

bash を構文解析しない。引数からパスらしいトークンを拾うだけなので、クォートや変数展開の
向こう側は見えない。拾い損ねたパスは「事実なし」になり、jev の判断がそのまま通る。
事実は通す方向にしか働かないので、見落としは危険側には倒れない。
